## 1. Технологии передачи трафика через транспортную сеть (L2VPN Huawei)

Когда в описании подинтерфейса видишь `-ccc-` или `-l2vc-` — это не протокол связи, а **способ организации виртуального канала (псевдопровода) поверх MPLS/Ethernet-магистрали** между двумя узлами.

| Термин | Что означает |
|---|---|
| **CCC** (Circuit Cross Connect) | Простейший L2VPN — статическая "сшивка" двух интерфейсов без сигнализации, настраивается вручную |
| **L2VC** (Layer 2 Virtual Circuit) | Псевдопровод с динамической сигнализацией через LDP — гибче, строится между узлами не напрямую связанными физически |
| `##ccc##`, `-ccc-`, `-l2vc-` | Одно и то же обозначение технологии, просто разное оформление в имени (решётка/дефисы) — на смысл не влияет |

**Суть простыми словами:** обе технологии создают "виртуальный провод" между двумя точками сети, хотя физически трафик идёт через общую магистраль.

## 2. Виды трафика мобильной сети, которые ходят через эти каналы

| Термин | Расшифровка | К какому поколению сети относится | Что переносит |
|---|---|---|---|
| **RAN** | Radio Access Network | Общее | Радиоподсеть — часть сети между абонентом/БС и ядром |
| **s1** | S1-интерфейс | 4G (LTE) | Между eNodeB и EPC. S1-MME — сигнализация, S1-U — пользовательский трафик. Обычно самый "тяжёлый" по объёму |
| **Gb** | Gb-интерфейс | 2G (GSM) | Между BSS и SGSN, пакетные данные GPRS/EDGE |
| **3g_data** | Iu-интерфейс (data plane) | 3G (UMTS) | Между RNC и SGSN, пользовательский трафик 3G |
| **3g_oam-for-U2000** | OAM-трафик | 3G | Служебное управление оборудованием, идёт к системе управления **U2000** (NMS от Huawei), НЕ абонентский трафик |
| **sigtran** | Signaling Transport | 2G/3G (в основном) | SS7-сигнализация поверх IP (через SCTP + M3UA/M2UA) |
| **GRX** | GPRS Roaming eXchange | Общее | Отдельная защищённая межоператорская сеть для роумингового трафика (не через обычный интернет) |
| **voip** | Voice over IP | Общее / IMS | Голосовой трафик, упакованный в IP (RTP + сигнализация) |

## 3. Diameter, HSS/HLR, s6a — сигнализация абонентской базы

- **HSS** (Home Subscriber Server) — база абонентов для **4G/IMS**.
- **HLR** (Home Location Register) — её предшественник для **2G/3G**. Часто одна платформа совмещает обе роли → запись `HSS/HLR`.
- **Diameter** — протокол AAA-сигнализации (аутентификация/авторизация/учёт), пришёл на смену RADIUS. Состоит из множества интерфейсов с буквенными кодами.
- **s6a** — конкретный Diameter-интерфейс между **MME** и **HSS**: используется при подключении абонента к LTE для проверки его профиля.

**Пример разбора строки:** `##ccc_HSS-Phoenix_s6a_BB03##` = псевдопровод CCC, несущий Diameter-сигнализацию по интерфейсу s6a к HSS на площадке Phoenix.

> ⚠️ **BB03/BB04** — предположительно внутренний идентификатор направления/линка (возможно, дублирующие пути к одному HSS). Точную расшифровку нужно уточнить у коллег — это внутренняя конвенция компании, не отраслевой стандарт.

## 4. IMS — IP Multimedia Subsystem

Архитектура ядра сети, которая переносит голос/видео/сообщения **поверх IP**, а не по классической коммутации каналов. По сути — VoLTE и есть реализация IMS в 4G.

Ключевые узлы IMS (для общей ориентации, не для зубрёжки):

| Узел | Роль |
|---|---|
| P-CSCF | "Входная дверь" — первая точка контакта телефона с сетью |
| S-CSCF | Маршрутизация звонка, применение правил |
| I-CSCF | Находит нужный S-CSCF для абонента |
| HSS | База абонентов (та же, что и для доступа в сеть) |
| MGCF/MGW | Шлюзы к старым (не-IMS) телефонным сетям |

Протоколы внутри IMS: **SIP** (установление сессий звонка), **Diameter** (сигнализация к HSS и политикам качества, интерфейсы Cx, Rx и др.).

## 5. Наименование узлов сети — как расшифровывать

Пример: `to MEL_TVK-FMC01 Eth-Trunk1` в описании интерфейса — это просто пометка **"этот линк идёт к узлу с таким именем"**.

Предполагаемая логика имени: `[РЕГИОН/город]_[площадка]_[тип оборудования]_[номер]`

| Фрагмент | Вероятный смысл |
|---|---|
| DON, RND, SIM, KRS, MEL | Донецк, Ростов-на-Дону, Симферополь, Краснодар, Мелитополь |
| AR | Aggregation Router |
| ASBR | Autonomous System Border Router |
| FMC | ~~Тип/роль узла (уточнить у коллег)~~ Изменено: это переименованный AGR |

## 6. Роуминг vs Интерконнект

| | Роуминг | Интерконнект |
|---|---|---|
| Кто перемещается | Абонент физически меняет сеть | Никто — трафик идёт между сетями, абоненты остаются каждый в своей |
| Пример | Абонент МТС в сети другого оператора за границей | Абонент МТС звонит абоненту Мегафона, оба дома |
| Сигнализация | Diameter s6a/s6d к HSS/HLR — проверка "свой ли абонент" | Сигнализация между коммутаторами/шлюзами двух сетей (SS7/SIGTRAN, SIP на границе) |
| Транспорт | Часто через GRX/IPX | Через точки присоединения сетей, тоже может идти через IPX/GRX |
| Деньги | Гостевой оператор выставляет счёт домашнему за обслуживание абонента | Операторы рассчитываются за пропуск трафика (транзит, терминация) |

**Экономика роуминга:** твой оператор платит гостевому оператору **оптовую цену** (wholesale) за твой трафик, а с тебя берёт **розничную цену** по твоему тарифу/пакету. Разница между ними — и есть заработок оператора. Расчёты между операторами по роумингу идут через файлы формата **TAP** (Transferred Account Procedure).

## 7. OSI-модель — что реально важно на практике

| Уровень OSI | Важность для инженера транспортной сети | Комментарий |
|---|---|---|
| L1 Физический | Базово | Кабели, оптика, скорости |
| L2 Канальный | **Высокая** | Ethernet, VLAN, Eth-Trunk, L2VPN (ccc/l2vc) — ежедневная работа |
| L3 Сетевой | **Высокая** | IP-адресация, маршрутизация между регионами |
| L4 Транспортный | Средняя | TCP/UDP + особенно **SCTP** (используется в SIGTRAN) |
| L5 Сеансовый | Не нужно | На практике как отдельной сущности почти не существует |
| L6 Представления | Не нужно | Аналогично, функции "размазаны" по другим уровням (TLS и т.п.) |
| L7 Прикладной | Точечно | Не весь уровень целиком, а конкретные протоколы: Diameter, SIP, SNMP |

> 💡 **Важно понимать:** в реальности сеть работает по 4-уровневой модели **TCP/IP**, а не по 7-уровневой OSI. OSI — удобный учебный язык для разговора о проблеме ("на каком уровне затык"), но уровни 5-6 в реальном стеке протоколов почти не встречаются как отдельные сущности.

**Приоритет развития:** глубже копать L2/L3/L4 + конкретные прикладные протоколы отрасли (Diameter, SIP, SNMP), а не абстрактную теорию верхних уровней OSI.

## 8. RS-485 — нужно ли знать?

**Не относится к основной работе.** Это интерфейс из мира промышленной автоматизации (АСУ ТП) — датчики, счётчики, ПЛК, обычно поверх него работает Modbus RTU.

**Единственная точка пересечения:** вспомогательная инфраструктура телеком-площадок — датчики температуры/влажности в серверной, контроллеры ИБП, дизель-генераторы — иногда отдают телеметрию именно по RS-485/Modbus через шлюз в Ethernet. Если в Zabbix появятся элементы вроде "температура в шкафу" или "статус ИБП" — вот тогда это может всплыть.

## 9. Физическая архитектура базовой станции (RAN)

Полезно понимать, что стоит на "другом конце" тех каналов, которые ты мониторишь.

| Элемент | Роль |
|---|---|
| **BBU** (Baseband Unit) | "Мозг" БС — обработка сигнализации, распределение ресурсов, точка выхода трафика на транспортную сеть (оптика, 100 Мбит/с – 1 Гбит/с) |
| **UMPT** | Главный модуль BBU — хранит настройки, обрабатывает сигнализацию GSM/UMTS/LTE |
| **UTRP** | Доп. транспортный модуль — прибавляет ~2 Гбит канала при нехватке ёмкости |
| **WBBP** | Модуль связи BBU с радиомодулями (для UMTS) |
| **RRU** (Radio Remote Unit) | Радиомодуль у антенны — преобразует сигнал между BBU и эфиром |
| **CPRI** | Оптический интерфейс между BBU и RRU — переносит сервисные и сигнальные данные |
| **SingleRAN** | Концепция: один радиомодуль/шасси поддерживает сразу 2G/3G/4G |
| **BSC / RNC** | Контроллеры, к которым подключается BBU: BSC — для 2G, RNC — для 3G |

**Связь с твоей таблицей:** BBU → BSC отвечает за трафик `Gb` (2G), BBU → RNC за `3g_data`/`3g_oam`, BBU → EPC за `s1` (4G). То есть физическое оборудование БС и логические каналы в мониторинге — это разные стороны одного и того же соединения.
